OmaCap 0.1.3 exports GIFs of the whole edit, with far less memory.

## Changes

- GIF export covers the whole edit, like MP4. The timeline decides what's kept, and the separate "Duration in seconds" limit is gone.
- Long GIFs no longer need gigabytes of memory. A 60-second, 1280-wide, 30 fps GIF peaked at 656 MB instead of 7.1 GB and finished in 38 seconds instead of 65.
- GIFs are sharper and smaller. They're made from a lossless render instead of an H.264 copy, and each frame only redraws the part that changed. The same 60-second test produced 3.6 MB instead of 5.1 MB.
- Long exports no longer fail when an FFmpeg step takes more than two minutes.
- The export message shows the file size and warns when a GIF is over the 10 MB limit that GitHub and Discord apply. The export dialog no longer shows a size estimate, which could be off by 50 times.

## Install or update

Download `omacap-0.1.3-1-x86_64.pkg.tar.zst` and `SHA256SUMS` from the assets below. In the download directory, run:

```sh
sha256sum --check --ignore-missing SHA256SUMS
sudo pacman -U ./omacap-0.1.3-1-x86_64.pkg.tar.zst
```

Finish or export your current edit before reopening OmaCap. GitHub releases do not update through `yay` or the Omarchy updater.

If you previously used the per-user installer, `~/.local/bin/omacap` and its desktop entry can take precedence over the package. See the README's installation section when switching installation methods.

## Validation and limits

Built against Omarchy stable, with capture/edit/export tests and a fresh-container installation and launch check. The PR also passed on current Arch. The export test now checks that a GIF lasts as long as the edit. The 60-second measurements above came from the app's exporter on a synthetic 1440p recording.

GIFs are silent, and busy motion makes large GIFs. Use MP4 for long or detailed clips. Real portal, microphone, and camera behavior still depends on your devices and desktop. Keep a recorded window at a fixed size; use display capture when resizing windows. This release targets short SDR recordings on a 16:9 output canvas.

`BUILD-INFO.txt` identifies the exact source commit and build environment. The assets include the source archive, standalone `PKGBUILD`, and checksums.
