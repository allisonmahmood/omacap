OmaCap 0.2.0 takes screenshots as well as recordings, and works like Omasnap, Omarchy's screenshot tool.

## Changes

- **One picker for both.** `omacap` freezes the screen: drag an area, click a window, or click empty space for the whole monitor. `V` switches to recording, and `omacap --record` opens it in record mode. The picker opens on the focused monitor and follows the pointer to another one, until you start picking.
- **Screenshots are copied and saved straight away**, framed with the look you used last, and a preview appears in the corner. The editor has Omasnap's tools: arrows, boxes, text, numbered steps, highlighter, spotlight, redaction, cut-out bands, OCR, scrolling capture, recent shots and pins. OmaCap adds its backdrop, frame and glass.
- **Recording** starts from a small bar for the microphone, camera and desktop audio, then a three-second countdown. The same key stops it, and a card in the corner offers Edit and Export.
- **Nothing of OmaCap is in a recording.** The area is cropped as it's captured, the outline and timer sit outside it, and every other OmaCap window and notification hides while recording. If the display changes mid-recording, the file ends before the change.
- **The video editor draws over your dimmed desktop**, with every control it had before. `W` moves it into a normal window.
- **Recordings are kept in your Videos folder** as `omacap-<date>_<time>.mkv`, so closing or discarding an edit no longer deletes them. Opening an OmaCap recording keeps its desktop audio.
- **Preview audio follows the default output**, so disconnecting headphones no longer silences playback.
- `omacap shot.png` and `omacap --clipboard` open an existing image, and "Open with OmaCap" works for PNG, JPEG and WebP.

## Updating from 0.1.3

Running `omacap` now opens the picker rather than the start window. Bind two keys in `~/.config/hypr/bindings.lua`, then run `hyprctl reload`:

```lua
o.bind("SHIFT + PRINT", "OmaCap screenshot", "omacap")
o.bind("ALT + SHIFT + PRINT", "OmaCap record", "omacap --record")
```

Keep "OmaCap" and "record" in the record binding's description; the countdown uses it to tell you which key stops recording. A 0.1.3 binding to `omacap --screenshot` keeps working.

Finish or export your current edit before updating. Pacman installs the new dependencies, including `layer-shell-qt` and Tesseract for OCR.

## Install or update

Download `omacap-0.2.0-1-x86_64.pkg.tar.zst` and `SHA256SUMS` from the assets below. In the download directory, run:

```sh
sha256sum --check --ignore-missing SHA256SUMS
sudo pacman -U ./omacap-0.2.0-1-x86_64.pkg.tar.zst
```

GitHub releases do not update through `yay` or the Omarchy updater.

If you previously used the per-user installer, `~/.local/bin/omacap` and its desktop entry take precedence over the package. See the README's installation section when switching installation methods.

## Validation and limits

Built against Omarchy stable, with Omasnap's smoke tests, the integration tests and a fresh-container installation and launch check. The PRs also passed on current Arch. Recordings made through a real screen-cast portal in a nested Hyprland were decoded frame by frame, and none contained an OmaCap pixel, including when the display's scale, resolution or orientation changed mid-recording. OmaCap was in daily use on an Omarchy desktop for a week before this release.

Rotated monitors can't be recorded yet. A display change during a recording ends it, keeping everything up to the change. Exports still need Xwayland. On a monitor that draws a software cursor, Hyprland includes the cursor in captures. Real microphone and camera behaviour depends on your devices, so check a short recording first. GIFs are silent, and this release targets short SDR recordings on a 16:9 canvas.
